# CHAT 1 — ЛОР  (владелец: `lore/**`)

Ты пишешь текст и только текст. JS, CSS, HTML — не твоё. Единственный интерфейс с сайтом — `lore/manifest.json`.
Прочти `docs/PLAN.md` перед стартом, особенно пункты 3 и 4.

**Цель:** из двух досье сделать цельный архив из 14 записей, где всё связано, ничего не противоречит,
и читатель может восстановить одну общую картину из фрагментов.

## ЭТАП 1. КАНОН (делать первым, без него остальное разъедется)

**L-01. `lore/CANON.md` — библия мира.** Это не для сайта, это твоя внутренняя правда. Разделы:

1. **Ядро.** Место — не локация, а бухгалтерия. Что такое «секунда», «долг», «шов», «квитанция».
2. **7 законов места.** Законы раунда как законы мира, а не игровая механика: почему нельзя выйти, что считается оплатой, кто ведёт счёт.
3. **Хронология.** Единая шкала: `До обряда → Ночь обряда (год) → Первые раунды → Настоящее`. Все досье привязываются к ней датами/номерами ночей.
4. **Матрица связей.** Таблица 11×11 (10 персонажей + Место): кто знал кого, кто чей долг, кто чей убийца. Из неё автоматически рождаются `related` в манифесте.
5. **Уровни достоверности.** Каждое досье — источник одного из трёх типов:
   - `КАНОН` — запись самого места, непротиворечива;
   - `СВИДЕТЕЛЬСТВО` — рассказ выжившего, пристрастен;
   - `СЛУХ` — обрывки, могут врать.
   Этот тег идёт в `meta` манифеста и его рисует сайт — он даёт читателю право не верить тексту.
6. **Табу.** Список того, что в этом мире невозможно. Проверяй каждую главу на нарушение.

**L-02. Таблица дел для карт.** 10 карт = 10 дел. В `CANON.md` таблица: карта → номер дела → 1 строка события → ссылка на LR-XXX. Chat 3 свяжет это с вкладкой «Карты».

**L-03. `lore/_TEMPLATE.md` — шаблон досье.** Структура одинаковая для всех:

```
# LR-XXX — Имя

<!--ch kto|ГЛАВА 01|Кто это и откуда известно-->

<!--ch nachalo|ГЛАВА 02|До места-->

<!--ch dolg|ГЛАВА 03|Как он попал в счёт-->

<!--ch drugie|ГЛАВА 04|Кого он знал-->

<!--ch ishod|ГЛАВА 05|Чем закончилось-->

<!--ch protivorechie|ГЛАВА 06|Что не сходится-->

<!--ch svyazki|СВЯЗАННЫЕ ЗАПИСИ|См. также-->
```

Последняя глава — «сшивки»: 2–5 абзацев, ссылающихся на другие дела текстом (`см. LR-006`) — Chat 3 сделает их кликабельными.

## ЭТАП 2. КАРКАС АРХИВА

Писать в этом порядке — каждый следующий опирается на предыдущий.

- **L-04. LR-013 «Словарь архива».** 25–40 терминов с расшифровкой. Ввести термины здесь, потом использовать везде. Термин без записи в словаре — ошибка.
- **L-05. LR-012 «Правила раунда».** 7 законов из канона, живым языком, со слов выживших. Каждый закон — 1 глава.
- **L-06. LR-011 «Хронология».** Событийная лента с датами и «номерами ночей». Якорная запись: на неё ссылается половина архива.
- **L-07. Реткон `lore/chronos.md` и `lore/place.md`.** Привести к канону: имена, даты, термины. Достроить главу «Связи» в каждом. `chronos.md` остаётся в режиме `ranges` — **строки глав не сдвигать**, иначе поедут `from/to` в манифесте.
- **L-08. Обновить `lore/manifest.json`** по каждой готовой записи: `status: "ready"`, `file`, `sub`, `meta` (с уровнем достоверности), `teaser`, `foot`, `tocFoot`, `download`, `related`.

## ЭТАП 4. СВЯЗНОСТЬ (ради этого всё и затевается)

- **L-19. Одна ночь — три взгляда.** Событие «ночь на поле» описывается в 3+ досье разными голосами. Расхождения обязательны: канон = пересечение всех версий. Это главный приём связки.
- **L-20. Круговые ссылки.** Проверить, что если A ссылается на B, то B объясняет свою версию связи. Ни одной односторонней ссылки.
- **L-21. Предметы как улики.** Medkit и остальные предметы = вещдоки с номерами. Расписать 6–10 предметов в `CANON.md` (название, чей, откуда) — Chat 3 вынесет их в данные, Chat 2 — отрисует.
- **L-22. Прогресс архива.** В `CANON.md` список «рекомендованный порядок чтения» из 14 записей — Chat 3 сделает из него кнопку «читать по порядку» и счётчик `восстановлено X / 14`.

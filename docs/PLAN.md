# FORSAKEN — план на 3 параллельных чата

Документ-договор. Все три чата читают его **первым делом** и не меняют.

---

## 0. Главное правило

Один файл — один владелец. Чат не редактирует чужие файлы **никогда**, даже «на одну строчку».
Нужна правка в чужом файле — пишешь запрос в `docs/task-*.md` своего чата в раздел «ЗАПРОСЫ К ДРУГИМ ЧАТАМ», и владелец делает это сам.

## 2. Маркеры в `index.html` — единственная общая точка

Уже расставлены. Пиши **только между своими** маркерами, существующие строки не трогай:

```html
<!-- SHARED-HEAD:B -->   ...   <!-- /SHARED-HEAD:B -->
<!-- SHARED-HEAD:C -->   ...   <!-- /SHARED-HEAD:C -->
<!-- SHARED-BODY:B -->   ...   <!-- /SHARED-BODY:B -->
<!-- SHARED-BODY:C -->   ...   <!-- /SHARED-BODY:C -->
<!-- SHARED-SCRIPTS:C --> ...  <!-- /SHARED-SCRIPTS:C -->
```

Chat 1 в `index.html` не заходит вообще.

## 3. Контракт лор ↔ код: `lore/manifest.json`

`lore/manifest.json` — единственный интерфейс между лором и сайтом. Уже создан, лежит скелет всех 14 записей.

- **Chat 1** наполняет его (`file`, `status: "ready"`, главы, `teaser`, `meta`, `related`).
- **Chat 3** переводит `app.js` с хардкода `LORE_DOCS` на `fetch("lore/manifest.json")`.
- После этого Chat 1 может добавлять досье **бесконечно и без единой строчки JS**.

Схема записи:

```json
{
  "id": "twotime",              // ключ, латиница, уникальный
  "record": "LR-002",           // номер дела
  "name": "Two Time",
  "role": "KILLER|SURVIVOR|PLACE|ARCHIVE",
  "cat": "characters|place|other",
  "file": "lore/lr-002-twotime.md",
  "status": "ready|planned",
  "img": "assets/twotime.png",  // опционально
  "teaser": "одна строка для карточки",
  "sub": "подзаголовок в шапке читалки",
  "fileLabel": "ЛОР-ДОСЬЕ // LR-002",
  "meta": ["5 ГЛАВ", "≈ 8 МИН ЧТЕНИЯ", "СВИДЕТЕЛЬСТВО"],
  "foot": "подпись в подвале досье",
  "tocFoot": "TWO TIME · LR-002",
  "download": "LR-002_TwoTime.md",
  "requires": "place",          // id досье, которое надо прочитать до конца (null = открыто)
  "related": ["LR-001", "LR-005"], // номера связанных дел
  "mode": "markers",            // "markers" = главы из <!--ch ...--> внутри .md
  "chapters": "auto"            // "auto" в режиме markers, массив — в режиме ranges
}
```

## 4. Формат лора (обязателен)

Файл `.md`, главы размечаются маркерами прямо в тексте:

```
# LR-002 — Two Time

<!--ch верность|ГЛАВА 01|Кто считал Azure другом-->

Первый абзац. Абзацы разделяются пустой строкой.

Второй абзац. *Курсив* — через звёздочки, больше никакой разметки в тексте нет.

<!--ch dolg|ГЛАВА 02|Долг, который он взял на себя-->
```

Правила:
- Разделитель абзацев — **пустая строка**. Внутри абзаца переводы строк не делать.
- Формат маркера строго: `<!--ch <id>|<KICKER>|<Заголовок>-->`. Пробелов внутри `<!--ch` не добавлять.
- Разметки HTML, заголовков `##`, списков, таблиц — **нет**. Парсер их не понимает.
- `*текст*` → курсив. Всё остальное экранируется.
- Один персонаж = 4–9 глав, 3–7 абзацев на главу. Длиннее — читалка становится неудобной.

## 5. Версии кэша

`?v=8` в `index.html` **никто не трогает во время работы**.
Финальный мерж-чат поднимает всё до `?v=9` одной правкой.

## 6. Порядок работы

1. Три чата работают параллельно, каждый в своей зоне.
2. Chat 3 первым делом делает манифест-загрузчик со **встроенным fallback на текущий хардкод** — чтобы сайт не падал, пока Chat 1 пишет файлы.
3. Каждый коммитит только свои файлы, мелким шагами.
4. Финал: проверка в браузере, bump `?v=9`, обновление `README.md`, пуш.

## 7. Единые соглашения

- CSS: только классы-префиксы своей зоны — `v2-` у Chat 2, `fx-` у Chat 3. Чужие классы не переопределять.
- JS: новый код Chat 3 — в IIFE, без глобальных переменных кроме `window.FX`.
- Тексты на сайте — по-русски, названия персонажей — как в игре (латиница).
- Никаких выдуманных чисел в статистике: только из Roblox-страницы или уже имеющихся данных.
- Ассеты: ничего не удалять, `assets/maps/source/` неприкосновенен.
